| Участок | Что есть в коде | Следствие для менеджера |
|---|---|---|

| `Recurse` / `ProcessOne` | Индексируют loose-файлы; POSIX-вариант собирает, сортирует и обходит пути. | `ProcessArchive` / `LoadArchive` | Читают заголовок/`auto_load`, ShoC-дешифрование, файловые записи, entry point и архивный индекс. | Сохранить форматы, смещения, декомпрессию, `vfs_idx` и lifetime архивов. Не писать альтернативный архивный загрузчик для игры. |

| `FS_Path::_update`, `PlatformLinux.inl` | На Android `xr_fs_strlwr` ничего не делает. Есть проба исходного регистра и fallback в lowercase. | Нельзя считать Android FS нечувствительной к регистру. Пакеты с неоднозначным регистром требуют отклонения или отдельного явного преобразования. |
| `CResourceManager::_CreateTexture`, `LS_Load`, `CScriptEngine` | Текстуры, шейдеры и script namespaces кэшируются по именам. | Смена источника того же имени не обновляет готовые GPU/Lua-ресурсы. Первая версия переключает профиль только перед новым запуском движка, без hot reload. |

Bundled `res/soc/fsgame.ltx` сначала сканирует `_appdata_` и каталоги архивов, затем `gamedata` и его подкаталоги. Поэтому loose-оверлеи обычно перекрывают архивные ресурсы именно в этом порядке. Это **не** универсальное правило «loose всегда выше архива»: победитель зависит от последней регистрации.

`$game_data$` сейчас указывает на `<game-root>/gamedata`; `$game_saves$`, `$logs$`, `$screenshots$` зависят от `$app_data_root$`. Текущий `-overlaypath` перенаправляет app-data/log roots, а не задаёт многослойный поиск ресурсов. Нельзя выдавать его за готовую систему мод-профилей.

Первое подключение — `work/thermal-power-20261023/restore_today.py`, проверка всех 28 UI-состояний, точного исходного `user.ltx` и 12 save-файлов по процедуре `NEXT_THERMAL_OPTIMIZATION_SESSION.md`. До успешного восстановления новую APK не устанавливать.
2. Принять независимые stability-патчи и повторные циклы Launcher → Game → Exit → Settings. Host-тест не доказывает устранение пользовательского вылета.
3. Разделить port compatibility assets и user mod assets. `OpenXRayActivity::extractAssetFolder` сейчас перезаписывает loose `.script/.vs/.ps/.s/.h`; `installFsgameConfig` устанавливает bundled config. Мод, скопированный туда вручную, может быть изменён при следующем запуске. Совместимые исправления порта должны иметь собственное происхождение, версию и обязательный уровень.
4. Укрепить чтение недоверенных `.db*`: длины заголовков, partial reads, арифметику диапазонов и release-проверки. Исправление mmap failure не заменяет эти проверки. В первой версии host-импорта `.db*` намеренно запрещены.
5. Учесть `Register` с `string256` для полного пути. Ограничение виртуального пути в манифесте не доказывает допустимость длинного Android private path. Перед активацией проверять окончательные пути либо отдельно менять внутреннее хранение имён с совместимыми тестами.

## Модель хранения

Предлагаемая структура (пока **не создана на устройстве**):

```text
<app-private-mod-root>/
  staging/<transaction-id>/              # импорт, не виден движку
  installed/<mod-id>/<version>/<digest>/  # неизменяемый проверенный payload
  profiles/<profile-id>/
    profile.json                         # точные версии и порядок
    saves/                               # только сохранения этого профиля
    config/                              # настройки профиля
    logs/
    cache/<engine-and-content-fingerprint>/
  transactions/                          # journal + восстановление импорта
```

Retail `.db*` остаются в пользовательском game-root. Не копировать гигабайты оригинальной игры и не менять её файлы. Vanilla-сохранения остаются на прежнем месте. Создание modded profile не переносит их автоматически; импорт сохранения в модифицированный профиль — отдельная явная операция с копией, никогда обратная перезапись vanilla.

Private storage уменьшает риск чужой модификации между валидацией и запуском, но требует учёта места и политики удаления приложения. Экспорт/backup профилей — отдельная функция; нельзя считать Android allowBackup гарантией сохранности большого пользовательского контента.

Версия пакета хранится неизменяемо и привязывается к digest содержимого. Уже установленную пару `(id, version)` с другим digest нельзя тихо заменить. Удаление payload допустимо только при отсутствии ссылок активных/сохранённых профилей и engine session.

## Манифест, зависимости и совместимость

Начальный формат JSON, схема 1:

```json
{
  "schema_version": 1,
  "id": "example_visuals",
  "name": "Example visuals",
  "version": "1.0.0",
  "game": "soc",
  "port_min_version": "1.6.2",
  "abis": ["arm64-v8a"],
  "backends": ["native_gles", "angle_vulkan"],
  "dependencies": [
    {"id": "required_base", "min_version": "1.0.0", "max_version_exclusive": "2.0.0"}
  ],
  "conflicts": ["alternative_visuals"]
}
```

Host parser принимает ограниченный UTF-8, отвергает повторные JSON-ключи, неизвестные поля, неподдерживаемую схему/игру, неверные типы, дубликаты зависимостей, self-dependency и некорректные диапазоны. Версии — ограниченные тройки `major.minor.patch`; prerelease/build metadata пока не реализованы. Строка версии APK `1.6.02-*` не должна неявно сравниваться лексикографически: интеграции нужен отдельный нормализованный compatibility version.

`Profile` хранит точные `ModRef(id, version)`. `ProfileManager` проверяет наличие версии, полные зависимости, диапазоны, циклы, конфликты, объявленные ABI/backend/port version и явный порядок. Зависимость должна предшествовать использующему её моду. Менеджер не переставляет моды за пользователя: это могло бы изменить победителя ресурсов.

Объявленная совместимость не доказывает, что сторонние Lua, DDS, OGF, shaders или saves действительно работают на ARM64/GLES/ANGLE. Требуется отдельная техническая проверка форматов и runtime smoke test. Нативные `.dll/.so`, исполняемые APK/JAR/DEX и чужие исполняемые файлы в первом импорте запрещены. Обычные Lua-моды тоже меняют игровую логику и не становятся безопасными от наличия JSON-манифеста.

## Приоритет и расширение существующей VFS

Предлагаемый порядок снизу вверх:

1. Retail archives и базовые loose-файлы, поведение текущего vanilla запуска сохранено.
2. Обязательный compatibility layer порта с версией, проверенными shaders/scripts и политикой перекрытия защищённых файлов.
3. Моды в явном порядке профиля; последний слой выигрывает.
4. Необязательный пользовательский override-слой с теми же проверками происхождения.

**Порядок compatibility layer пока проектное решение.** Для защищённых Android shaders/scripts нельзя разрешать незаметную замену непроверенным модом. При конфликте с защищённым файлом предпочтительнее блокировать активацию до специального compatibility declaration, чем молча ломать свет/AI или незаметно игнорировать мод. Никаких защищённых списков в production ещё не добавлено.

Предпочтительная будущая реализация: расширить `CLocatorAPI` данными `mount/provider identity`, логическим корнем, приоритетом, физическим loose-путём и цепочкой кандидатов при `Register`. Для архивов использовать текущий архивный `vfs_idx/ptr/size`; победитель остаётся в текущем lookup index. `r_open_impl` получает тот же reader через существующий путь. Диагностический export списка `(virtual key, provider, hash, priority)` позволит сравнивать план менеджера с фактической FS.

Не добавлять Java/Python callback для каждого `FS.r_open`, не распаковывать все `.db*`, не подменять ResourceManager и не вводить независимый runtime-поиск путей рядом с `CLocatorAPI`.

Нынешний `unload_archive` даже после удаления всех дескрипторов не восстанавливает перекрытый нижний слой. Поэтому первый production-вариант не выгружает моды на лету: применяет полностью проверенный mount plan до загрузки ресурсов и освобождает его после завершения всех читателей/потоков. Работающий engine в текущем manifest не выделен в `android:process`; безопасная граница рестарта должна следовать итогам lifecycle-аудита, а не предположению о существующем отдельном процессе.

## Индекс, конфликты и cache

Host `FileEntry` содержит относительный логический путь, размер и SHA256. Начальная политика путей — lowercase ASCII, запрет `..`, абсолютных имён, Windows drive/ADS, control/NUL, обратных слешей, reserved names, неоднозначных trailing-dot/space. Это консервативная политика импорта, **не изменение поведения Android VFS**. Файлы с другими именами не переименовываются автоматически.

`FileConflictDetector` сохраняет весь список providers и различает одинаковые и разные hashes. Совпадение content hash означает одинаковые байты файла, но не совместимость двух модов в целом. Конфликт `scripts/foo.script` требует ручного слияния/compatibility patch; автоматическое текстовое слияние Lua/LTX в первую версию не входит.

`FileResolver` host-модели проверяет детерминированное правило «последний слой выигрывает». Его положительный и отрицательный кэш принадлежат неизменяемой generation; новый профиль/содержимое/backend/build получают новую generation. В production движковый index должен воспроизводить тот же план. Shader cache дополнительно учитывает renderer, GPU/driver, shader compiler и реальные shader defines — текущий host fingerprint не объявляется готовой заменой shader-cache key движка.

Смена профиля: завершить игру → дождаться окончания native threads/readers/resources → выбрать/проверить профиль → атомарно сохранить activation journal → новый запуск движка с профильными aliases и mount plan. При ошибке следующего старта предлагать возврат к vanilla без удаления мода и saves. Точный recovery UI/transaction protocol пока не реализованы.

## Безопасный импорт архивов

Уже реализован **только dry run** `inspect_zip`:

- Перед созданием списка ZIP members проверяются размер исходника, EOCD, количество записей и размер central directory; split/ZIP64/нестандартный layout отклоняются. Preflight и `ZipFile` используют один открытый file handle.
- Проверяются root `mod.json`, расположение payload только внутри `gamedata`, unsafe paths, повторы, file/directory collisions, symlinks/special entries, encryption, compression method и коэффициент сжатия.
- Ограничиваются объявленные и реально прочитанные размеры; данные читаются порциями, проверяются CRC средствами `zipfile`, вычисляются SHA256. Манифест ограничен 64 KiB.
- Ничего не распаковывается, не исполняется, не записывается в game-root и не монтируется. Test fixtures создаются только в private host temporary folders.

До реального Android-импорта ещё нужны: SAF/URI stream handling, cancel/resume, disk-space budget, package hash, копия неизменяемого входа в quarantine, no-follow создание файлов в новом private staging, ownership/permission checks, durable journal, атомарная публикация и recovery после process death. После копирования повторно проверять размер/хэши и не доверять source path, который сторонний процесс мог изменить. Реализация RAR/7z и `.db*` не входит в этот прототип; не добавлять тяжёлые native decompressors без отдельного выбора, лицензий и bounds tests.

Моды являются доверенным пользовательским контентом, не sandboxed-кодом. Защита импорта от traversal не доказывает безопасность выполнения чужих скриптов или разбора всех форматов движком.
