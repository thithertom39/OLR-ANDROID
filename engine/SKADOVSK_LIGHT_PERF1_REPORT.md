## Подтверждённая лишняя работа и минимальное исправление

`CRender::render_lights` вызывается для `LP_normal` и `LP_pending` из `src/Layers/xrRender_R2/r2_R_render.cpp`. Каждый shadowed light ожидает подготовку subspace, рисует геометрию и вызывает `Details->RenderShadow` со своим фрустумом. Ранее известный GLES-путь проверял видимые экземпляры травы для каждого света, предварительно настраивая shader/material/uniforms, даже если весь набор модели заведомо находился вне области тени.

Теперь один вызов `render_lights` получает стековый `GLDetailShadowCull::BoundsBatch`. Для каждой модели и варианта травы строится консервативная суммарная AABB текущего неизменяемого списка видимости. Она переиспользуется между локальными источниками внутри этого пакета. Если вся AABB вне **того же существующего** фрустума света, пустой проход пропускается до установки программы и перебора отдельных экземпляров. Если граница пересекается, неизвестна, невалидна или не помещается в кэш, выполняется прежний путь.

Изменены:

1. `src/Layers/xrRenderGL/glDetailShadowCull.h`: ограниченный кэш 3 × 64, `BoundsBatch`, `BatchBounds`, `UnionBounds`, точный разбор A/B-флага. Функции исходного per-instance `Build` и `Outside` по математике не изменены.
2. `src/Layers/xrRenderGL/glDetailManager_VS.cpp`: консервативная проверка целой модели перед подготовкой шейдера. Полная амплитуда ветра для всех фаз и направлений; исходные матрицы и `scale_calculated`. Только известные стандартные detail vertex programs и local-shadow контекст.
3. `src/Layers/xrRender_R2/r2_R_lights.cpp`: scope времени жизни кэша на один пакет света.

Кэш не живёт между кадрами, normal/pending пакетами или загрузками уровня. Нет heap allocations, сохранения указателей на экземпляры и конкурентного GL. Nested/thread-local scopes и несовпадение владельца предусмотрены. Пересчёт видимости завершён существующим ожиданием task перед использованием. Список `m_visibles`, матрицы и масштабы не меняются между этими локальными проходами; амплитуда берётся из текущего `swing_current`, поворот ветра покрыт целиком.

Для пересекающейся модели исходный цикл culling/upload/draw от `u32 dwBatch = 0` до конца файла **побайтно совпадает с базой**. Main pass и солнечные каскады вызывают обычный `Details->Render`, без local-shadow TLS-фрустума, и новым отсечением не затрагиваются. Не менялись плотность, расстояния, пороги, качество теней, разрешение, эффекты, физика, AI или игровой баланс.

Отдельно просмотрены `src/Layers/xrRender_R2/render_phase_sun.cpp` (`render_sun::render`, `accumulate_cascade`) и GLES legacy sun `src/Layers/xrRenderPC_GL/r2_R_sun.cpp` (`render_sun_old::render_sun_near`, `render_sun`, `flush`). Измеренной причины для изменений солнечного пути в текущей выборке нет. Его затраты и видимость/OCCQ оставлены под существующими раздельными scopes.

## Итерации и доказательства CPU-причины

Первая попытка `light-lazy1` только заранее проверяла, есть ли хоть один выживший экземпляр. Она дала небольшое различие (29.88 против 28.49 FPS), недостаточное для уверенного вывода и повторяла дорогой перебор. Поэтому добавлен пакетный envelope-кэш `light-bounds2`. В финальном `light-perf1` удалён лишний повторный pre-scan пересекающихся моделей: они сразу идут в исходный цикл.

Инструментированные промежуточные прогоны, последние 20 полных CPU samples каждого:

| CPU этап | lazy1, мс | bounds2, мс |
|---|---:|---:|
| local_lights, inclusive | 17.39 | 8.07 |
| local_shadow_details, inclusive | 10.51 | 1.39 |
| details_all_submissions, inclusive | 10.82 | 1.73 |

В обоих прогонах `detail_instances_submitted` = **10348**. Общий draw count слегка отличается (5230–5233 против 5226–5228) из-за живой сцены; нельзя объявлять все draw calls идентичными. В `bounds2` последний недописанный JSONL fragment исключён явно (строка 93); полные записи сохранены. Эти CPU числа относятся к промежуточным вариантам, а не выдаются за точные этапные GPU/CPU числа финальной APK.

## Ограничения и что проверить пользователю

Автоматизированные instrumented прогоны после background/resume не получили завершённых GPU query records: ring_full рос, GPU rows = 0. Это **недоступные измерения, не нулевая GPU-нагрузка**. Первопричина проблемы запросов не установлена; нельзя объявлять доказанным context-loss/driver bug. Пользовательский исходный непрерывный прогон имел валидные GPU записи. Профилировщик и schema 3 не менялись этим патчем. Повторный uninterrupted прогон без сворачивания нужен для точного сравнения GPU-интервалов.

Не выполнены длительный heat soak, полный обход Затона, отдельная ночная сцена с травой у близких ламп и новая SoC игровая регрессия. Отдельные screenshot совпадают по композиции, но не побитно из-за ветра/оружия/птиц/NPC; полная пиксельная идентичность не заявляется. Код и контракт гарантируют сохранение исходного набора принимаемых экземпляров для проверенных условий, аппаратные проверки картинки всё равно нужны.

Порядок пользовательской проверки: открыть тот же сейв, выбрать привычный API, не менять графику, посмотреть тяжёлый ракурс и пройти к кораблю; проверить тени травы от фонарика/ламп вблизи и в движении, смену ракурса, дождь/солнечную погоду. Для A/B выйти штатно, добавить `-gles_detail_eager_setup`, загрузить тот же save/камеру, сравнить после прогрева и затем удалить флаг. Не сохранять benchmark поверх оригинального quicksave.
