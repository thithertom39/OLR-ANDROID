# R2: сохранённый результат 23.11.2026

R1 безопасно заморожен, R2 получил проверенное уменьшение направленной просадки.
Стабильные 60 FPS при 1920×1080 НЕ достигнуты. Это частичный результат по исходным
критериям: остаются стоимость геометрии и непроверенные игровые условия. Работа
остановлена по запросу; R1 самостоятельно не возобновлять.

## Что исправлено и почему

1. **Повторные проверки detail-геометрии для локальных теней.** В тяжёлом
направлении видимы 13 shadowed-источников, около 3,3 тыс. draw calls. Старый
путь повторно строил индивидуальные bounds десятков тысяч экземпляров травы
для каждого источника. Включён существующий консервативный cache cell bounds
на один неизменяемый light package. Группа вне frustum источника пропускает
только индивидуальные проверки; у выживших групп остаётся исходный predicate.
Wind envelope, формулы, порядок экземпляров, шейдеры, свет и тени сохранены.
Неизвестные шейдеры/некорректные bounds/нехватка scratch используют исходный путь.
В Full HD CPU local lighting P50: **5,89 → 2,95 мс**; CPU main geometry
остаётся около 7–8 мс. Число shadow passes и фактически нужных draws не урезано.

2. **GLES core vertex bindings.** Проверка только desktop ARB extension
ошибочно выбирала старые per-attribute pointer calls на GLES 3.2. Настройка
деклараций и смена VB теперь согласованно используют ES 3.1 core при наличии
всех функций; ES 3.0 сохраняет fallback. Форматы/normalization/stride/base offset
не изменены, `glDrawElementsBaseVertex` не используется. Отдельный ранний A/B
не показал существенного выигрыша от этой замены; основное измеренное
ускорение связано с detail-cell culling, не приписывается vertex API.

3. **Вылет при загрузке несовместимого сохранения.** Существующий `olr.sav`
имеет header version 3, текущий загрузчик ожидает минимум 7. Прямой autoload
обходил проверку меню и доходил до fatal assertion в ALife. Android start теперь
проверяет файл штатным CSavedGameWrapper до Server::Connect и использует
существующее завершение неудачного старта с возвратом в главное меню.
Файл не исправлялся, не конвертировался и не перезаписывался. Это не доказывает
совместимость старых PC saves с текущим портом. Валидный контрольный save
продолжает загружаться.

4. Восстановлен отсутствовавший upstream LuaJIT host CMake и штатный CI.
Профилирование остаётся отдельной сборкой. Дополнительная проверка cell culling
доступна только в diagnostic build; поиск её флага вынесен из внутреннего цикла.

## Сопоставимые измерения на физическом Galaxy Tab S9

Save `r1_checkpoint_20261121`, позиция примерно `(-209.188, -5.945, -145.350)`.

## Проверки и границы доказанного

- NDK/C++ и release APK: локально и CI успешно.
- Реальный Mesa ES 3.2: 17 форматов вершин, 85/85 pixel comparisons (включая
  VAO/VB switches, stride и ненулевое смещение), GLES errors отсутствуют в probe.
- Conservative bounds: 122000 проверок исходного predicate, 15250 отклонённых
  групп; package lifetime, invalid bounds и отрицательные flags проверены.
- Adreno: 17,88 млн sampled reference tests в фактических rejected cells,
  mismatches=0. Проверочная сессия не использована для CPU performance.
- Обычная финальная APK: валидный Cordon save, Full HD, поворот/движение;
  отсутствие новых fatal/shader compilation сообщений в этих логах.
- Несовместимый `olr.sav`: исходный вылет воспроизведён, после guard процесс
  остаётся жив и возвращается в главное меню. Валидный save повторно проверен.
- Хеши четырёх пользовательских save-файлов совпали; тестовые изменения
  `vid_mode`/`load_last_save` отменены, исходный user.ltx восстановлен побайтно.
  Launcher возвращён к исходному 1080p Screen 1728×1080 и пустым custom args.
- После каждого теста игра закрыта, экран выключен. Температуры и thermal status
  сохранены; многочасовых прогонов, stay-awake и изменений thermal/performance
  controls не было. Точная максимальная температура: см. final-verified.json.

Скриншоты A/B сохранены, но точная scene pixel parity не доказана из-за
неполностью одинакового yaw/анимации/погоды. Визуальная модель и настройки
не упрощались; это подкреплено bounds/reference и vertex-format тестами.
Полный визуальный регресс NPC/оружие/вода/ночь/все эффекты не завершён.
Существующие shader-version/unsupported-blender предупреждения присутствуют
и в baseline; новые критические скриптовые ошибки в тесте контрольного save
не обнаружены. Загрузка через конкретные кнопки главного меню отдельно не доказана.
Расширенный KHR_debug audit обнаружил 64 сообщения `unable to delete shader
object %d` до лимита callback. Повтор на неизменённой baseline APK дал те же
64 сообщения и тот же текст: новая регрессия этим не подтверждается. Ошибка
удаления shader objects не исправлена; полная проверка «GLES без ошибок» НЕ
пройдена, более поздние сообщения могли быть скрыты лимитом. Логи:
`logs/gles-debug-comparison.json`, `logs/baseline-debug-audit`, `logs/final-valid-save`.
Точная причина/handle ownership требует отдельной локализации в `SH_Atomic.cpp`
и `ShaderResourceTraits.h`; неподтверждённое исправление не вносилось.

## Что осталось

Стабильные 60 FPS / 16,67 мс P95 в тяжёлом Full HD направлении не получены.
Остаются около 3300 обычных draws, main-geometry CPU 7–8 мс и значительная
стоимость GPU timeline; изолированного GPU-busy результата нет. Их дальнейшее
сокращение без потери качества требует отдельного доказательства batching/state
sorting либо точного GPU trace. Не объявлять текущее ускорение полным устранением
всех направленных просадок. Новые большие оптимизации не начинались.

Совместимость старого save version 3 не реализована; файл сохранён. Нужны
отдельные сцены с водой, несколькими NPC, оружием, ночью и в помещениях,
сопоставимая длительная игровая проверка и при необходимости shader/blender
compatibility. R1 остаётся замороженным; следующая работа только по отдельному
запросу пользователя.
